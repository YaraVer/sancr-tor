# Сравнение механик: `prototype.html`, веб-репозиторий и `sancr-tor-godot`

Документ для заказчика: показывает, **что уже сделано в каждом артефакте**. Технологии разные (один HTML-файл на Canvas 2D, Phaser-веб-приложение, Godot 4 + GodotJS), поэтому сравниваются именно **игровые механики и продуктовая готовность**.

- `prototype.html` — исходный однофайловый пиксельный прототип.
- `sancr-tor` — https://github.com/YaraVer/sancr-tor , веб-прототип (Vite + Phaser + TypeScript), **с PSS-10**.
- `sancr-tor-godot` — https://github.com/YaraVer/sancr-tor-godot , настольная версия (Godot 4 + TypeScript), **без PSS-10**.

---

## Сводка

| Слой | `prototype.html` | `sancr-tor` (web) | `sancr-tor-godot` |
|---|---|---|---|
| Формат | Один HTML-файл, inline JS, без сборки | Vite + Phaser 3, TypeScript | Godot 4.6 + GodotJS, TypeScript |
| Экраны | Титул, согласие, код, PSS, игра, итоги, пауза | Титул, согласие, код, карта, режим, PSS, история, бой, итоги | Меню, карта, миссия (проверка/бой), итоги, «об игре» |
| Источник текста | Inline JS-объекты | `public/data/story.json` + `endings.json` + `ui.json` | `data/missions/*.json` + `endings.json` + `ui.json` |
| Графика | Процедурный пиксель-арт | 32×32 пиксель-спрайты, переход к 2D планируется | Гладкая процедурная 2D, без пиксель-арта |
| PSS-10 | Есть, до и после игры, два режима отсутствуют | Есть, до и после игры, два режима | **Намеренно отсутствует** |
| Данные/тесты | Всё хардкод, тестов нет | JSON + 55 тестов vitest | JSON + 52 теста vitest |
| Сеть | Нет (только Google Fonts) | Нет | Нет |

| **Флаги и ветвление** | ~20 флагов, текст/проверки/бой | Флаги влияют на исход, проверки и бой | Флаги влияют на исход, проверки и бой |

| **Тесты и CI** | Нет | 55 тестов, GitHub Actions (Pages пока не включён) | 52 теста, smoke, `--tour`, `--shot` |

## Что это значит для этапа проекта

1. **`prototype.html`** — самый механо-насыщенный по «железу» (ретраи в бою, d100-события, лечение), но весь контент зашит в один файл, нет сохранения и тестов.
2. **`sancr-tor` (web)** — сейчас наиболее полный демонстрационный стенд: E1–E10, два режима PSS, карта, проверки, бой, логи, сохранение и автотесты. Осталось перейти от пиксель-арта к гладкой 2D и включить GitHub Pages.
3. **`sancr-tor-godot`** — устойчивая база для дальнейшего расширения сценария и механик, с чистой 2D-графикой и тестами; PSS туда сознательно не добавляется.

## Рекомендуемый следующий шаг

- Включить GitHub Pages в настройках веб-репозитория и перезапустить workflow.
- Графику развивать от пиксель-арта к гладкой 2D: сначала портреты и фоны иллюстрациями, затем параллакс/анимация.
- Оставить PSS и будущие тесты подключаемыми модулями: `public/data/tests/index.json` уже позволяет добавлять новые шкалы без правки кода.
- При необходимости углубить бой (лечение, ретраи, d100-события) — перенести оставшиеся механики из `prototype.html` в данные веб-версии.
