# Сравнение механик: `prototype.html` и `sancr-tor-godot`

Документ для заказчика: наглядно показывает, **что уже сделано в каждом прототипе**, а что пока осталось за кадром. Технологии разные (один HTML-файл на Canvas 2D против Godot 4 + TypeScript), поэтому сравниваются именно **игровые механики и продуктовая готовность**, а не код.

- `prototype.html` — исходный однофайловый прототип (`C:\Users\USER\Downloads\prototype.html`, также лежит в корне веб-репозитория).
- `sancr-tor-godot` — https://github.com/YaraVer/sancr-tor-godot , настольная версия на Godot 4.6 + GodotJS/TypeScript.

---

## Сводка по слоям

| Слой | `prototype.html` | `sancr-tor-godot` |
|---|---|---|
| Формат | Один HTML-файл, inline CSS/JS, Canvas 2D, без сборки | Проект Godot, TypeScript → `.godot/GodotJS`, сцена `main.tscn` |
| Экраны | Титул, согласие, код участника, PSS (до/после), игра, завершение, пауза | Меню, миссия (диалог + выбор), итоги, «Об игре», ошибка данных |
| Источник текста | Внутри JS-объектов `EP`, `ENDINGS`, `FINAL_CH` | `data/missions/*.json`, `data/endings.json`, `data/ui.json`, `data/characters.json` |
| Графика | Процедурный пиксель-арт через `fillRect`, палитра `PAL` | Процедурная **гладкая 2D**: градиенты, арки, туман, силуэты по палитрам |
| Данные | Хардкод в JS | Всё в JSON + валидация схемы и 27 юнит-тестов |
| PSS-10 | Есть, **до и после** игры | **Намеренно отсутствует** по требованию к десктопной версии |
| Сохранение | Нет (только ручной экспорт JSONL/CSV в буфер) | Локально в `user://choice_log.jsonl` и `user://runs.jsonl` |

## Детальное сравнение механик

| Механика | `prototype.html` | `sancr-tor-godot` | Статус |
|---|---|---|---|
| **Сюжет E1–E10** | Да, 10 эпизодов с text variants и флагами | Да, 10 эпизодов по 3 реплики + выбор, всё в JSON | В обеих версиях |

| **Проверки d20 / d100** | Да, броски с логом (E4, E6, E8, E9, финал) | Нет (решения только через выборы и флаги) | **Только в прототипе** |

## Что это значит для этапа проекта

1. **`prototype.html` — самый механо-богатый артефакт**: карта, тактический бой, d20/d100, PSS до и после, логи и экспорт. Но весь контент зашит в один файл, нет сохранения, нет тестов, пиксельная графика.
2. **`sancr-tor-godot` — самая устойчивая база для роста**: данные отделены от кода, есть валидация, тесты, локальное хранение, чистая гладкая 2D-графика. Но в нём намеренно нет PSS и пока нет карты/боевой системы.
3. **Веб-репозиторий `sancr-tor`** после текущих изменений станет промежуточным звеном: те же выборы и E1–E10, но с **двумя режимами** (с PSS-10/логированием и без), окнами опросника **до и после** игры и локальным сохранением результатов. Это и есть наиболее понятный для заказчика «живой» прототип текущего этапа.

## Рекомендуемый следующий прототип

- Взять за основу веб-репозиторий как демонстрационный стенд: режимы, PSS pre/post,
  лог выборов, нейтральные итоги.
- Перенести из `prototype.html` только лёгкие механики: флаги, d20-проверки и одну компактную сцену боя — как данные в JSON, а не хардкод.
- Графику развивать от пиксель-арта к гладкой 2D: сначала заменить портреты и фоны иллюстрациями, затем подключить параллакс/анимацию.
- Оставить PSS и другие тесты как **подключаемые модули**: `data/tests/*.json` + общий движок опросников, чтобы позже добавлять новые шкалы без правки кода.
