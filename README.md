# Крипты Санкр-Тор (веб-прототип)

Веб-прототип нарративной RPG «Крипты Санкр-Тор»: история E1–E10, выборы с скрытыми метками реакций,
концовки и **два режима прохождения** — с психологическим тестированием PSS-10 и без него.
Параллельно развивается настольная версия на Godot: https://github.com/YaraVer/sancr-tor-godot .

## Два режима прохождения

Режим выбирается после экрана согласия (`ModeSelectScene`):

| Режим | Что делает |
|---|---|
| **С PSS-10 и журналом** | Опросник **до игры** (исходный уровень) и **после игры** (итоговый); логи выборов с метками `D/C/G`, `pss_item`, временем ответа; итог и обе суммы PSS сохраняются локально. Результат PSS показывается только по нажатию кнопки «Показать PSS». |
| **Без тестирования** | Только история и концовка. Опросник не показывается, логи и PSS-результаты не пишутся. |

Оба режима проходят одну и ту же историю из `public/data/story.json`.
Ответы и логи **никогда не отправляются в сеть** — только `localStorage` этого браузера (или память вкладки, если браузер запретил хранение).
Экспорт логов в JSONL — кнопкой в итогах, через буфер обмена / консоль.

## Ключевая логика PSS

- Сюжет E1–E10 содержательно связан с пунктами PSS-10 по меткам `pss_item` (1–10); выборы логируются с метками `D/C/G` (скрыто от игрока).
- В режиме с тестированием стандартизированный опросник предъявляется **дважды**: до и после истории, в классической форме вне сюжета. В режиме без тестирования — не предъявляется вообще.
- Подсчёт: 10 пунктов, шкала 0–4, обратные пункты `[4,5,7,8]`, субшкалы `distress` и `coping`, общий балл 0–40.
- Результаты показываются только по явному запросу игрока; без диагностических выводов.
- Архитектура рассчитана на **другие тесты в будущем**: реестр `public/data/tests/index.json` перечисляет опросники и фазы (`pre_game` / `post_game`). Чтобы добавить новую шкалу, положите её JSON в `public/data/tests/` и добавьте запись в реестр.

Подробная спецификация: `CRYPTS_SANCR_TOR_WEB_PROJECT.md`.
Сравнение механик с `prototype.html` и Godot-версией: `docs/PROTOTYPE-COMPARISON.md`.

## Где лежит текст истории

- **Исполняемый сценарий:** `public/data/story.json` — 10 эпизодов с репликами, локациями, вариантами выборов, исходами, эффектами и флагами. Это тот файл, который правится при расширении сценария.
- **Концовки и письмо Бронна:** `public/data/endings.json`.
- **Авторская спецификация сюжета** (стиль, E1–E10, соответствие пунктам PSS): `CRYPTS_SANCR_TOR_WEB_PROJECT.md`, разделы 4–5.
- Старая папка `public/data/events/` зарезервирована под поэпизодные файлы, если понадобится дробить историю.

## Установка и запуск

```bash
npm install
npm run dev
```

Потом: титул → согласие → выбор режима. Отладочные URL — ниже.

## Проверки

```bash
npm test            # 27 тестов: подсчёт PSS, данные, логика режимов, локальное хранение
npm run build       # tsc -b && vite build
npm run sprites:check
```

## Графика

- **Текущий этап — пиксель-арт.** В проекте используются 32×32 idle-спрайты (8 направлений): `celestina`, `tan`, `hirdmen-shieldwall`; рендер Phaser настроен с `pixelArt: true`.
- **Следующий этап — гладкая 2D.** Когда персонажи и сцены будут отрисованы как иллюстрации, пиксель-спрайты будут заменены; в Godot-версии пиксель-арт не используется изначально.
- Рантайм-ассеты: `public/assets/` (см. `public/assets/README.md`). Очередь и промпты: `design/source/GRAPHICS-TASKS.md`.
- Проверка спрайтов: титул → «Проверка спрайтов» или `http://localhost:5173/?scene=SpritePreviewScene`.
- Импорт пака: `npm run sprites:import -- --zip "<path>.zip" --id zereks --name "Зерекс"`.

## Публикация (GitHub Pages)

Сайт собирается и публикуется автоматически при каждом `git push` в `main`
(workflow: `.github/workflows/deploy.yml`).

Один раз после создания репозитория:
**GitHub → Settings → Pages → Build and deployment → Source: GitHub Actions.**

> Пока Pages не включён, workflow падает на шаге `configure-pages` с ошибкой
> `Resource not accessible by integration` — это ожидаемо. Включите Pages и
> перезапустите последний run (Actions → Deploy to GitHub Pages → Re-run all jobs).

Адрес: `https://<username>.github.io/sancr-tor/`

- `base: './'` в `vite.config.ts` — относительные пути, поэтому одна и та же сборка работает и локально, и на Pages-подпути.
- Workflow сначала запускает `npm test`, потом `npm run build`; упавший тест останавливает деплой.
- Браузерная версия — статический сайт: PSS-результаты и логи никуда не отправляются.

## Отладочные параметры URL

- `?scene=SpritePreviewScene` — проверка спрайтов.
- `?scene=ModeSelectScene` — сразу выбор режима.
- `?scene=PssFormScene` — форма опросника (по умолчанию фаза `pre_game`).
- `?scene=StoryScene` — сразу эпизоды (нужна созданная сессия).
- `?scene=ResultsScene` — итоги (нужна созданная сессия).
- `?scene=PostGamePSSScene` — обратная совместимость: та же форма с фазой `post_game`.
- `?debug=1` — доступ к `window.__game` (Phaser) в консоли.

## Примечания

- Формулировки пунктов в `public/data/pss10.json` следует сверить с первоисточником (Золотарёва А.А., 2023, русская версия PSS-10) перед исследовательским использованием.
- Не коммитить секреты API; ключ провайдера задаётся через переменную окружения (см. `opencode.json`).
- PSS и будущие тесты — не диагностика и не медицинская рекомендация.
